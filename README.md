# Estimand-Protocol Mapping Tool

臨床試験の **Estimand（推定目標）** を起点として、プロトコルに記載された関連規定、試験運用上の成立条件、確認に必要な観測データを整理するための研究用プロトタイプです。

本ツールは、AIに品質上の判断を委ねるものではありません。プロトコル原文に基づく情報整理を支援し、臨床試験に関わる専門職がレビュー・議論するための「たたき台」を作ることを目的としています。

## 背景と目的

臨床試験では、Estimandを定義するだけでなく、その解釈を成立させるためのプロトコル規定が適切に実施され、必要な情報が観測可能であることが重要です。

本ツールでは、以下の順序で情報を整理します。

```text
Estimand
  ↓
関連するプロトコル規定
  ↓
Estimandを成立させるための条件
  ↓
条件が維持されているか確認するための観測データ
  ↓
CTQ要因およびリスク候補
```

これにより、Estimandと試験実施、モニタリング、データマネジメント、Risk-Based Quality Management（RBQM）の接続を検討しやすくすることを目指しています。

## 主な機能

- Estimandの5要素の入力
  - 関心のある治療
  - 対象集団
  - 変数（評価項目）
  - 中間事象（ICE）の取扱い
  - 集団レベルでの要約
- プロトコルPDFから関連規定を抽出
- 対象集団、変数、ICEおよび有害事象対応に関する規定の整理
- 各規定を成立させるために必要な条件の整理
- 条件の維持を確認するために必要な観測データの整理
- CTTIの考え方を参考にしたCTQ要因の検討
- 解析結果のテキスト出力

## 想定する利用者

- 臨床試験の計画・運営に関わる研究者
- 医師、CRC、CRA、データマネージャー、統計担当者
- RBQM、Quality by Design、中央モニタリングを検討する担当者
- Estimandと試験運用の関係を学習・研究する方

## 使い方

1. サイドバーでAIの接続方法を選択します。
2. Estimandの5要素を入力します。
3. 解析対象となるプロトコルPDFをアップロードします。
4. 「解析を開始」を実行します。
5. 出力されたプロトコル規定、成立条件、観測データを原文と照合します。
6. 必要に応じて「CTQ（信頼性リスク）を深掘りする」を実行します。
7. 結果をダウンロードし、専門職間のレビューや議論に利用します。

## AI接続

現在、以下の接続方法に対応しています。

- Google Gemini API
- LM StudioなどのOpenAI互換ローカルAPI

Gemini APIを使用する場合はAPIキーが必要です。ローカル環境を使用する場合は、既定では以下のエンドポイントへ接続します。

```text
http://localhost:1234/v1/chat/completions
```

## ローカルでの実行

### 1. リポジトリを取得

```bash
git clone https://github.com/chan-kuwa/estimand.git
cd estimand
```

### 2. 依存パッケージをインストール

```bash
pip install -r requirements.txt
```

### 3. Streamlitアプリを起動

```bash
streamlit run ass.py
```

Gemini APIキーをStreamlit Secretsで設定する場合は、`.streamlit/secrets.toml` に以下を記載します。

```toml
GOOGLE_API_KEY = "your-api-key"
```

## CTTI参照データについて

CTQ深掘り機能では、実行環境に配置されたCTTI参照データを利用できます。現在の実装では、アプリと同じディレクトリにある `000111598.xlsx` を読み込み、原則として「日本語訳」シートを参照します。

参照ファイルがない場合でも基本的なプロトコル解析は実行できますが、CTTI参照情報はプロンプトに追加されません。

## 重要な注意事項

### 研究用プロトタイプ

本ツールは研究および思考検証を目的としたプロトタイプです。妥当性、再現性、完全性、実務上の有用性は確立されていません。

### AI出力の確認

生成AIは、誤った記述、原文にない推論、参照箇所の取り違えなどを含む可能性があります。出力をそのまま意思決定や公式記録に使用せず、必ずプロトコル原文と照合し、臨床試験の専門家が確認してください。

### 機密情報・個人情報

外部APIを使用する場合、アップロードしたプロトコルのテキストが外部サービスへ送信されます。所属組織の規程、契約、情報セキュリティ要件を確認し、未公開情報、機密情報、個人情報を許可なく入力しないでください。

### 適用範囲

本ツールは、治験実施計画、モニタリング計画、統計解析計画、医学的判断、規制上の判断を自動的に決定または代替するものではありません。

## 理論的な位置づけ

本ツールは、主に以下の概念の接続を検討するために開発しています。

- ICH E9(R1)におけるEstimand
- Quality by Design
- Critical to Quality（CTQ）要因
- Risk-Based Quality Management（RBQM）
- CTTI Quality by Designの考え方
- 中央モニタリングおよび多職種によるリスク評価

特に、ICE strategyを個別症例の実施判断として扱うのではなく、Estimandの解釈を成立させるために必要なプロトコル規定と観測可能性を整理することに重点を置いています。
